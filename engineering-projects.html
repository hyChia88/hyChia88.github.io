01 / COLLABORATIVE HOUSING SEARCH PROJECT

UniNest

Combine lexical precision with semantic matching.

Housing queries mix explicit requirements with less precise descriptions. My contributions covered retrieval, image-to-text queries, and a refactor of the AI service layer within a collaborative application.

  • PostgreSQL
  • BM25 + semantic retrieval
  • RRF
  • FastAPI
  • Pydantic
  • Docker

Search implementation

  • Combined PostgreSQL BM25 and semantic vector retrieval using Reciprocal Rank Fusion.
  • Added image-to-text queries so visual input could enter the retrieval workflow.

Service implementation

  • Refactored a FastAPI application into an asynchronous AI gateway and model services.
  • Added Pydantic contracts and a swappable data-access layer to separate concerns.

Making changes repeatably testable

Added Ruff, mypy, and pytest CI checks, plus Docker Compose setup for reproducible development. These checks support code quality and repeatability; they do not replace retrieval-quality evaluation.

Scope: contributions to search and service modules within a team project. No throughput or relevance-improvement claim is made here.

02 / COURSE PROJECT · MODEL LIFECYCLE & SERVING

Movie Recommendation System

What happens after the ranking model is built?

A recommendation API needs useful behavior when a user is new, data changes, or a model cannot load. My work connected hybrid ranking with lifecycle controls, monitoring, and service fallbacks.

  • Collaborative + content-based ranking
  • Versioned artifacts
  • Drift checks
  • API fallbacks

Model lifecycle

  • Implemented versioned model artifacts and atomic model replacement to support updates and rollback.
  • Added data-quality checks, drift monitoring, and retraining hooks.

API reliability

  • Built collaborative and content-based recommendation behavior.
  • Added fallbacks for cold-start users and model-loading failures.
  • Exposed readiness and model metadata through health and status endpoints.

Design for a useful degraded response

Personalization can degrade without making the entire API unusable. Fallbacks and visible service state make this distinction explicit, while artifact versioning supports recovery from a problematic model update.

Scope: a production-style course project. This overview does not assert production deployment, a zero-downtime guarantee, or measured serving latency.
