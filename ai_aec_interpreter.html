An Interpreter Layer for AEC: Cross-Modal Grounding & Ontology-Driven Retrieval

A neuro-symbolic AI middleware that grounds site photos and field notes to specific IFC element GUIDs in a BIM model — hallucination-free, fully traceable.

Chia Hui Yen

M.Sc. Computational Design · Carnegie Mellon University

📄 Thesis (PDF) 📑 Slides ▶ Video Demo

The ProblemThe physical–digital traceability gap

AEC projects standardise on OpenBIM/IFC, yet day-to-day site coordination still runs on manual interpretive labour: people translate unstructured evidence — photos, chat messages, floorplan patches — into model-linked, schema-compliant records. The result is information loss across handoffs, ambiguous evidence-to-element links, and days of lag that decay into lost institutional knowledge.

AbstractOverview

Coordinating AEC projects means constantly translating messy site evidence into the structured BIM record — error-prone, manual work. This thesis asks: how can AI act as an interpreter middleware to reliably align unstructured site evidence with digital project data? We decompose it into (RQ1) multimodal grounding under ambiguity linking noisy evidence to specific IFC entities despite geometric repetition — and (RQ2) ontology-driven retrieval — turning probabilistic neural outputs into schema-compliant results without hallucination. The answer is a hierarchical neuro-symbolic architecture: a fine-tuned vision-language model extracts typed spatial constraints, and a symbolic layer runs a priority-ordered traversal over an enriched IFC knowledge graph, with a Graph-RAG reranker producing the final ranked candidates.

ContributionsWhat this work delivers

Reliability

Zero hallucinated GUIDs

The VLM never writes Cypher. A fine-tuned extractor emits a typed Constraints JSON that fills deterministic query templates — the system can only return GUIDs that exist in the model.

ML Engineering

Pipeline under zero real labels

An IFC Parse & Enrich engine generates training data deterministically from raw IFC files: structure mining → Blender synthesis with hard negatives → LLM-as-judge filtering → 990 grounded cases.

Architecture

Decomposable failures

Decoupling probabilistic extraction from deterministic retrieval removes black-box failure: every error is traceable to a specific stage (type, floor, or ranking).

ArchitectureThe neuro-symbolic interpreter

Five stages: multimodal input → neural extraction (VLM + LoRA) → Constraints JSON → symbolic retrieval (priority Cypher cascade over a Neo4j IFC graph) → Graph-RAG reranking → ranked GUIDs. Design rationale: reliability over flexibility (deterministic templates instead of Text-to-Cypher), and an IFC-native graph built from the schema itself rather than noisy document-level extraction.

Key ModulesHow it works under the hood

IFC Parse & Enrich Engine

Converts raw IFC into a query-ready Neo4j graph, enriching topology beyond native containment/fill with retrieval-oriented edges: NEXT_TO, CONNECTS_TO, ADJACENT_TO, ON_STOREY.

IfcOpenShell · Neo4j

Symbolic Planner

Nine priority strategies; the recall-preserving p0∪p1 union planner combines attribute filtering with spatial-topology ranking. Templates are deterministic — same input, same query, same result.

Cypher · priority cascade

Synthetic Data Pipeline

Skeleton-first generation fixes ground truth before adding stochastic visual evidence: IFC mining → Blender renders with hard negatives → Gemini text → LLM-as-judge filter → 990 cases, no real labels.

Blender · Gemini · LLM-as-judge

Deterministic Visual Heuristics

OpenCV handles counting and ordinal slot position; ResNet classifies element size bands. These inject discriminative cues into the reranker for sub-tasks VLMs do unreliably.

OpenCV · ResNet

The neural extractor is a fine-tuned Qwen2.5-VL (LoRA, G-series) that emits a structured contract {storey, ifc_class, spatial_relations:[{predicate, object_type, …}]} — reaching 82% direction accuracy where zero-shot Gemini scores 0%.

ResultsThe architecture is right; the gap is extraction

Headline: under perfect extraction the symbolic layer retains the correct element in 100% of cases and compresses the candidate pool from a median of 24 → 1. The architecture is provably sound — the remaining operational ceiling is bound by neural extraction quality, not by graph logic.

DemoOne case, end-to-end

A web demo (Streamlit / Gradio) takes an uploaded construction photo plus a natural-language description and highlights the matched IFC elements in a 3D viewer — runs in the browser, no AEC software required. A Grasshopper + Hops integration is a planned proof-of-concept.
